ブラウザだけで、Word と同じ見た目を。

Oxi は、Word 文書（.docx）をブラウザ上で Word そのままのレイアウトで表示・編集するためのオープンソースエンジンです。Rust + WebAssembly でゼロから実装し、再現度は実在の文書で Microsoft Word とページごとに照合。サーバーは使わず、ファイルは 1 バイトも外に出ません。

英語ブラインドセット — 初見の 50 文書

英語は最初から一番厳しい測り方をしています — 公開 docx-corpus から、修正のターゲットには一切使わない凍結ブラインドベンチ 50 文書。現行セットは blind-H50（種別ごとに未使用の次の SHA-256 順位、2026-10-02 に測定前凍結、規則は pipeline_data/FROZEN_BLIND_H.md）で、これがその唯一の測定です。英語で Oxi はピクセル 2 位（0.874） — ONLYOFFICE（0.918）に次ぎ、LibreOffice（0.858、50 文書中 32 文書で Oxi が Word に近い）を上回ります。Word とのページ数一致は Oxi 43/50、ONLYOFFICE 48/50、LibreOffice 42/50。増減したページを 0 点で数える penalized 平均は ONLYOFFICE 0.912、Oxi 0.845、LibreOffice 0.838、Polaris Office 0.792、GenOffice 0.737、SILURUS 0.726、eigenpal 0.671。真値は Microsoft Word（Microsoft 365 16.0.20430.20092）、比較対象は ONLYOFFICE 9.3.1.8、LibreOffice 26.8.0.3、Polaris Office 11.115、GenOffice 6a241c4、SILURUS @silurus/ooxml 0.86.1、eigenpal @eigenpal/docx-editor-react 1.9.0 — すべて 150 DPI。BetterOffice と OfficeCLI は今回の回では未完（ブラウザ描画中に測定機のメモリが尽きたため）。ブラインドは一度しか採点しないので、後から測って足すことはせず空欄のままにしています。

日本語ブラインドセット — 初見の 50 文書

日本語も同じ厳しさで測ります。現行セットは jaBlind-H50（2026-10-02 に測定前凍結。公開マニフェストの日本語 technical は枯渇しているため、その 5 枠は事前に宣言した規則で他種別の次の順位から補充 — 5 本とも forms）。Oxi はピクセルで首位（0.857）で、Polaris Office（0.828）に 0.029、LibreOffice（0.807、50 文書中 41 文書で Oxi が Word に近い）に 0.050 の差。今回はページ数一致も最多です（41/50、ONLYOFFICE は 39/50）。エンジンの順位は言語で入れ替わります — ONLYOFFICE は英語 1 位・日本語 6 位 — これが言語ごとにブラインドを持つ理由です。過去 3 つの日本語セットは当時のエンジンで 0.842 / 0.802 / 0.802。3 週間と 1 世代後の本セットが初めて 0.85 を超えました — ただし 1 サンプルなので、例の ±0.02 がそのまま付きます。

PowerPoint ブラインドセット — 初見の 48 デッキ

同じ測定規律を .pptx にも適用しています。公開データセット noxneural/pptx_collection_templates から（取得前に宣言したシードで）無作為抽出した 50 デッキを、Microsoft PowerPoint 自身の描画と 150 DPI で照合 — どのエンジンでも開けない破損ファイル 2 件を除き 48 デッキ。初回測定 0.679（2026-08-13）から 1 週間のレンダラ改善で 0.953（2026-08-20）に到達し、LibreOffice（0.913・ペア差 +0.040 ± 0.005、|t| = 8.7、48 デッキ中 44 で Oxi 優位）と ONLYOFFICE（0.908）を上回りました。スライド数は 3 エンジンとも 48/48 で一致、48 デッキ全てが改善して後退ゼロ、最下位のデッキでも 0.880 です。

Excel — 数式と VBA をブラウザで

.xlsx エンジンは依存グラフ型の数式エンジン（215 関数。実在の 285 ワークブックで Excel 自身のキャッシュ値と突き合わせて検証）と、ワークブックのマクロをブラウザで実行するクライアントサイド VBA ホストを備えています: Range / Worksheet / Workbook 操作、Sort、AutoFilter、Find、Copy/PasteSpecial、WorksheetFunction — 11 種のホストオブジェクトに 95 メンバ。それぞれ実物の Excel COM の挙動から導出し、82 本のスクリプト比較で検証しています。マクロによる編集は差分だけを書き戻し、元の ZIP は保持 — 無編集保存はバイト単位で同一です。

技術記事: VBA のオブジェクトの寿命を Rust の Rc<()> で再現する — Excel とまったく同じタイミングで Class_Terminate を実行する仕組み。

なぜこの精度が出せるのか

  • 100% クリーンルーム実装：逆アセンブルやバイナリ解析は一切行いません。仕様の根拠は公開標準（OOXML — ISO/IEC 29500 / ECMA-376）と、COM API 経由で Word の出力値を観測するブラックボックス測定の 2 つだけです。
  • デュアルフォントエンジン：Word のレイアウトは GDI の整数ピクセル丸めを前提に組まれているため、.docx では GDI の振る舞いをそのまま再現。そのしがらみがない形式には DirectWrite の浮動小数メトリクスを使います。
  • 回帰ゲート：すべての変更を全コーパスで検証。改ページの一致、要素の位置、ピクセル SSIM を毎回確認してから取り込みます。

詳細と再現スクリプト: README — Layout Accuracy · docs/layout_accuracy.md

日本語組版を、中心に

多くの Word 互換レンダラーで後回しにされてきた日本語レイアウトこそ、Oxi の実測の中心です。測定コーパス自体が、日本語レイアウトが最も難しい文書群——省庁の規程、行政の申請様式、雇用契約書——でできています。

  • 禁則処理 — JIS X 4051 に沿った行分割。行頭・行末禁則、約物の詰め、ぶら下がり組み。
  • 縦書き — 右から左に流れる縦組み。縦中横にも対応。
  • ルビ（ふりがな）、割注、圏点（傍点）。
  • 文字グリッド（docGrid） — Word の行グリッド・字送りモデルを忠実に再現。
  • 判子 — 丸印・角印・小判型の電子印鑑生成と PAdES PDF 署名。

技術

Rust + WebAssembly、形式に依存しない中間表現、そしてサーバーゼロ。

なぜ今なのか

2026 年、フランス（DINUM 指令）、スイス（連邦事務局）、ドイツ（OpenDesk）など、欧州の公共部門は Microsoft Office 離れを本格化させています。そしてどの移行でも、最後に残るのは同じ問題です — 手元にある大量の .docx が、Word と同じ見た目で開けるかどうか。Oxi は Word 再現度を「約束」ではなく「継続的な実測」で示すことで、この問題そのものをなくすことを目指しています。

アーキテクチャ

  • 完全クライアントサイド：解析・レイアウト・描画・編集はブラウザ内の WebAssembly で実行。サーバー基盤もアップロードも不要です。
  • 形式に依存しない中間表現：Document → Page → Block (Paragraph | Table | Image) → Run。OOXML にも ODF にも寄せていないので、往復変換で劣化しません。
  • ラウンドトリップ編集：元の ZIP を保持し、変更した XML テキストノードだけをパッチ。ファイルをゼロから作り直すことはしません。
  • 同梱フォントはオープンライセンスのみ：メトリクス互換のオープンフォントを使用し、プロプライエタリフォントは同梱しません。
  • 組み込み可能：wasm-bindgen の JavaScript API（parse_document、layout_document、edit_docx など）を任意の Web アプリから呼び出せます。

ライセンス

コアエンジンは MPL-2.0（ファイル単位コピーレフト。AGPL と違い、商用製品への組み込みも可能です）。WebAssembly / Python バインディングは MIT OR Apache-2.0。コントリビューションは DCO のみで CLA はありません。

よくある質問

無料で使えますか？

はい。オープンソース（コア MPL-2.0、バインディング MIT OR Apache-2.0）で、Web デモは登録不要・無料です。

ファイルはサーバーに送信されますか？

されません。処理はすべてブラウザ内の WebAssembly で完結し、ファイルが外部に送られることはありません。機密文書でも安心して使えます。

Word とどれくらい同じ見た目になりますか？

修正のターゲットには使わない初見文書だけの凍結ブラインドベンチマークで、Word とピクセル単位の SSIM を測定しています。英語 blind-H50（2026-10-02 凍結・測定）で Oxi は文書平均 0.874、Word とのページ数一致は 50 文書中 43。ピクセルでは ONLYOFFICE が上（0.918、48/50）、LibreOffice が下（0.858、42/50）。日本語 blind-H50 では Oxi が 0.857 で Polaris Office（0.828）と LibreOffice（0.807）を上回り、ページ数一致も最多（41/50）です。エンジンの順位は言語によって入れ替わるため、言語ごとにブラインドセットを持っています。 比較チャートと方法は精度の節を参照。

対応している形式は？

まずは Word の .docx です。ページレイアウトの完全再現とラウンドトリップ編集に集中しています。「Word の .docx 描画を忠実に再現する」ことが Oxi のミッションで、対応形式を広げるのはその先です。

自社製品に組み込めますか？

組み込めます。コアはファイル単位コピーレフトの MPL-2.0、バインディングは MIT OR Apache-2.0 なので、AGPL 系と違い商用・プロプライエタリ製品にも組み込めます。

オフラインでも動きますか？

ページと WebAssembly モジュールを読み込んだあとは、文書の表示も編集もネットワークなしで動きます。
